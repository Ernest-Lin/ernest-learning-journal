# Lec 08 - Secure the Web

## 1. 总体主线

Lec 08 接在 Lec 07 密码学后面，讲的是：

> 密码学算法怎样真正用在 Web 安全里。

Lec 07 重点是算法本身：

- symmetric encryption
- asymmetric encryption
- Diffie-Hellman
- RSA signature
- hash

Lec 08 重点是实际系统：

- HTTPS / SSL / TLS 怎么组合这些算法。
- public key 怎样被信任。
- certificate authority 如何解决公钥归属问题。
- password 为什么不能明文保存。
- 网络安全不只是技术，还包括人、流程、风险管理。

一句话串起来：

> HTTPS uses certificates and asymmetric cryptography to authenticate identities and establish keys, then uses symmetric cryptography to protect data transmission, but real security also depends on password protection, risk management, people and procedures.

## 2. Encoding 不等于 Encryption

### Encoding

Encoding 是把数据从一种形式转换成另一种形式。

例如：

- text 转 binary
- binary 转 hex
- binary 转 Base64

Decoding 是反向过程。

重点：

> Encoding is for representation, not for secrecy.

也就是说，encoding 的目的通常是方便存储、传输、显示，而不是保密。

## 3. Base64

Base64 是一种 encoding。

它常用于：

- 在文本协议里传输二进制数据。
- 在 email、HTTP、JSON 等文本环境中表示图片、文件或 token。
- 把不可见二进制转成可打印字符。

非常重要：

> Base64 is not encryption.

原因：

- Base64 没有 secret key。
- 任何人都可以 decode。
- 它不能提供 confidentiality。

考试如果问 “Is Base64 one kind of encryption?”：

```text
No. Base64 is an encoding method, not encryption. It only converts data into another representation and does not use a secret key. Anyone who knows the encoding rule can decode it, so it does not provide confidentiality.
```

## 4. HTTPS 为什么需要组合算法

Lec 07 讲过：

- symmetric encryption 快，但 key exchange 难。
- asymmetric encryption 可以解决身份和密钥交换问题，但速度慢。

所以 HTTPS/TLS 的设计思想是：

> Use asymmetric cryptography to authenticate and establish a session key, then use symmetric cryptography to encrypt the session data.

也就是：

1. 用非对称算法和证书确认服务器身份。
2. 通过 key exchange 生成 session key。
3. 后续大量数据用 symmetric encryption 传输。

考试句子：

```text
HTTPS combines asymmetric and symmetric cryptography. Asymmetric cryptography and certificates are used to authenticate the server and establish a secure session key. After that, symmetric encryption is used because it is much faster for bulk data transmission.
```

## 5. Public Key Management 的问题

非对称加密里 public key 可以公开。

但问题是：

> How do we know this public key really belongs to Alice, Bob, or a website?

如果 Eve 把自己的 public key 冒充成 Bob 的 key，Alice 就可能把秘密发给 Eve。

所以 public key management 的核心问题是：

- 如何验证 public key 的真正 owner。
- 如何管理大量 public keys。
- 如何建立 trust。

这就是 PGP、WOT、CA、PKI 要解决的问题。

## 6. PGP 和 Web of Trust

PGP 是 Pretty Good Privacy，常见于 email encryption。

PGP 使用 Web of Trust。

Web of Trust 的思想：

> Trust can be extended through signatures from people you trust.

例如：

- 你信任 Alice。
- Alice 签名确认 Bob 的 public key。
- 那么你可以间接信任 Bob 的 public key。

WOT 是 decentralized trust：

- 不依赖单一中心机构。
- 通过人与人之间的签名扩展信任链。

优点：

- 灵活。
- 不完全依赖中心 CA。

缺点：

- 普通用户难理解。
- 管理复杂。
- 不适合大规模浏览器自动验证网站。

## 7. Certificate Authority

CA 是 Certificate Authority。

它解决的问题：

> How to verify the real owner of a public key?

CA 的核心思想：

> Trust of a public key is based on the chain of trust to a trusted CA root.

浏览器和操作系统内置了一些 trusted root CAs。

网站证书由 CA 签发。

浏览器验证网站证书时，本质上是在检查：

- 这个证书是不是由可信 CA 签发。
- 证书链能不能追溯到浏览器信任的 root CA。
- 证书里的 domain name 是否匹配当前网站。
- 证书有没有过期。
- 证书有没有被吊销。

## 8. Certificate 的作用

证书把 public key 和 identity 绑定在一起。

证书里通常包含：

- 网站域名或组织信息。
- 网站 public key。
- 证书有效期。
- 颁发者 CA。
- CA 的 digital signature。

重点：

> A certificate proves that a public key belongs to a specific identity, such as a domain name.

网站申请证书时：

1. 网站管理员生成 key pair。
2. private key 留在服务器，不发送给 CA。
3. 把包含 public key 的 CSR 发给 CA。
4. CA 验证申请者是否真的控制该域名或组织。
5. CA 签发 certificate。

注意：

> Private key should never be sent to the CA.

## 9. Certificate Chain

CA 有很多层级：

- Root CA
- Intermediate CA
- Website certificate

浏览器通常直接信任 root CA。

网站证书可能不是 root CA 直接签发，而是由 intermediate CA 签发。

所以浏览器需要验证 certificate chain：

```text
Website certificate -> Intermediate CA -> Root CA
```

只要这条链最终能连到 trusted root CA，证书才可信。

考试句子：

```text
A certificate chain links a website certificate to a trusted root CA through one or more intermediate CAs. The browser verifies each signature in the chain. If the chain is valid and ends at a trusted root CA, the public key in the website certificate can be trusted.
```

## 10. SSL 和 TLS

SSL 是 Secure Sockets Layer。

TLS 是 Transport Layer Security。

现实中大家经常说 SSL certificate，但现代安全协议主要是 TLS。

重点：

- SSL 是较早的协议。
- TLS 是后续更安全的标准。
- SSL 3.0 已经不安全，例如 POODLE attack。
- TLS 不只用于 HTTP，也可以用于 FTP、SMTP 等。

考试可以写：

```text
SSL and TLS are protocols used to secure communication over networks. TLS is the newer and more secure successor to SSL. HTTPS is HTTP over TLS, but TLS can also be used by other protocols such as FTP and SMTP.
```

## 11. TLS 基本流程

TLS 要把这些东西组合起来：

- key exchange
- digital certificate
- digital signature
- symmetric encryption
- MAC / HMAC

简化流程：

1. Client 访问 HTTPS 网站。
2. Server 发送 certificate。
3. Client 用内置 root CA 验证 certificate chain。
4. Client 和 Server 通过 key exchange 生成 session key。
5. 后续通信使用 symmetric encryption。
6. 使用 MAC/HMAC 检查 message integrity。

非常重要：

> TLS cannot work securely by using only symmetric algorithms or only asymmetric algorithms. It combines both.

## 12. Cipher Suite

Cipher suite 是 TLS 中一组算法的组合。

它通常包括：

- key exchange algorithm
- authentication algorithm
- symmetric encryption algorithm
- MAC / hash algorithm

例如一个 cipher suite 会决定：

- 用 RSA、DHE、ECDHE 做 key exchange。
- 用 RSA 或 ECDSA 做 authentication。
- 用 AES 做 bulk encryption。
- 用 SHA 或 HMAC 做 integrity check。

考试重点不是背具体名字，而是知道：

> A cipher suite defines which algorithms are used together in a TLS connection.

## 13. Session Key

HTTPS 不是直接用 RSA 加密所有网页数据。

原因：

- RSA 慢。
- RSA 不适合加密大量数据。

实际流程是生成 session key。

课件里提到 session key 由以下内容参与生成：

- client random
- server random
- pre-master secret

然后双方根据这些数据生成同一个 session key。

后续通信使用 session key 进行 symmetric encryption。

## 14. 为什么需要 DH / ECDHE

如果只用 RSA key exchange，有一个问题：

如果服务器 private key 泄露，而且攻击者之前保存了加密通信内容，就可能解密历史通信。

这很危险。

DH / ECDHE 的作用：

> They provide forward secrecy.

Forward secrecy 的意思是：

> Even if the server private key is leaked later, previous session keys should not be recovered from recorded traffic.

所以 TLS 1.2 之后越来越强调 DHE/ECDHE。

课件也提到：

- TLS 1.3 removes RSA key exchange。
- TLS 1.3 减少 handshake，提高速度。
- TLS 1.3 的 cipher suites 更现代。

考试句子：

```text
Using Diffie-Hellman or ECDHE can improve forward secrecy. Even if the server's long-term private key is leaked later, attackers should not be able to decrypt previously recorded sessions because each session has its own temporary key.
```

## 15. MAC / HMAC

MAC 是 Message Authentication Code。

在 TLS 中，它用于检查 message integrity。

作用：

- 检查消息有没有被篡改。
- 确认消息来自拥有 shared secret 的一方。

HMAC 是基于 hash 的 MAC。

注意：

- Hash 本身不需要 key。
- MAC/HMAC 通常需要 shared secret。

考试句子：

```text
MAC is used to verify the integrity and authenticity of a message. In TLS, it helps detect whether a message has been modified during transmission.
```

## 16. HTTP Cookie 和 Session

HTTP 是 stateless。

Stateless 的意思：

> The server does not automatically remember previous requests.

但是电商网站需要记住：

- 谁登录了。
- 购物车里有什么。
- 用户当前状态。

所以需要 cookie 和 session。

### Cookie

Cookie 是浏览器保存的小文本数据。

它通过 HTTP header 在 browser 和 server 之间传递。

### Session

Session 通常存储在 server 端。

每个 session 有一个 unique session id。

浏览器通常通过 cookie 保存 session id。

流程：

1. 用户登录。
2. 服务器创建 session。
3. 服务器把 session id 放进 cookie。
4. 浏览器后续请求自动带上 cookie。
5. 服务器根据 session id 找到用户状态。

考试句子：

```text
HTTP is stateless, so cookies and sessions are used to maintain user state. A cookie is stored in the browser and often contains a session ID, while the actual session data is stored on the server.
```

## 17. CA 被攻击的风险

Lec 08 强调一个观点：

> The biggest danger is believing we are safe.

CA 系统不是绝对安全。

例子：

- DigiNotar 曾被黑客攻击。
- 攻击者伪造了 Google 证书。

这说明：

- 如果 CA 被攻破，攻击者可能伪造合法证书。
- 浏览器可能错误信任假网站。
- HTTPS 依赖 CA trust chain，因此 CA 本身是关键风险点。

考试可以写：

```text
The CA system is not absolutely secure. If a trusted CA is compromised, attackers may issue fake certificates for real domains. Browsers may trust these certificates because they chain back to a trusted root CA, which can enable man-in-the-middle attacks.
```

## 18. Password 不能明文保存

这是 Lec 08 后半部分的高频安全点。

原则：

> Never store passwords in plain text.

原因：

- 数据库泄露时，用户密码会直接暴露。
- 很多人多个网站复用密码，会引发 credential stuffing。
- 管理员也不应该看到用户明文密码。

正确做法：

> Store password hashes, not plain passwords.

登录时：

1. 用户输入 password。
2. 系统计算 hash。
3. 与数据库中保存的 hash 比较。
4. 如果一致，则登录成功。

注意：

> Hash is not encryption.

Hash 不能被解密，只能重新计算后比较。

考试句子：

```text
Passwords should not be stored in plain text. The system should store password hashes instead. During login, the entered password is hashed and compared with the stored hash. This reduces the damage if the database is leaked, and even administrators should not be able to see users' original passwords.
```

## 19. Rainbow Table

Rainbow table 是预先计算好的 password-hash 对照表。

攻击者可以用它快速查出常见密码的 hash 对应什么明文。

例如：

```text
SHA256("123456") = ...
```

如果很多用户密码都是常见弱密码，而且系统只存简单 hash，就容易被 rainbow table 攻击。

## 20. Salt

Salt 是给每个 password 加入的随机值。

存储时不是直接：

```text
hash(password)
```

而是：

```text
hash(password + salt)
```

Salt 的作用：

- 让相同 password 产生不同 hash。
- 增加 rainbow table 攻击成本。
- 防止攻击者用一张表攻击所有用户。

注意：

- Salt 不一定需要保密。
- Salt 应该随机且每个用户不同。

考试句子：

```text
Salt is random data added to a password before hashing. It makes identical passwords produce different hash values and makes rainbow table attacks much harder, because attackers cannot reuse precomputed hashes for all users.
```

## 21. Hash Collision

Hash collision 是两个不同输入产生相同 hash 输出。

例如：

```text
hash(A) = hash(B), but A != B
```

MD5 和 SHA-1 已经被证明存在实际碰撞风险，不适合安全场景。

王小云教授在 MD5、SHA-1 碰撞研究中非常重要，并参与 SM3 设计。

考试重点：

- MD5 不安全。
- SHA-1 不推荐。
- 安全系统应使用更强 hash，例如 SHA-256、SHA-3、SM3 等。

## 22. MFA / 2FA

MFA 是 Multi-Factor Authentication。

2FA 是 Two-Factor Authentication，是 MFA 的一种。

MFA 要求用户使用超过一种认证因素。

常见 factors：

- something you know：password
- something you have：phone, token, USB key
- something you are：fingerprint, face

好处：

即使 password 泄露，攻击者也可能无法登录。

考试句子：

```text
MFA improves security by requiring more than one authentication factor, such as a password plus a phone verification code. Even if the password is leaked, the attacker may still fail to log in without the second factor.
```

## 23. Credential Stuffing

Credential stuffing 是利用泄露的账号密码去撞其他网站。

原因：

- 用户在多个网站使用相同密码。
- 一个小网站泄露，攻击者拿密码去登录邮箱、支付、电商平台。

防御：

- 不同网站使用不同密码。
- 使用 MFA。
- 系统侧检测异常登录。
- 不明文保存密码。
- 使用强 password hashing 和 salt。

## 25. Phishing

Phishing 是通过伪装可信对象欺骗用户。

例如：

- 假邮件。
- 假登录页面。
- 假客服电话。
- 假短信链接。

攻击目标：

- password
- verification code
- bank card information
- private data

防御：

- 检查域名和证书。
- 不点击可疑链接。
- 使用 MFA。
- 安全培训。
- 风险监控。

## 26. DDoS

DDoS 是 Distributed Denial of Service。

攻击者通过大量设备向目标发送流量，让服务不可用。

它主要影响 CIA triad 中的：

> Availability

防御思路：

- traffic filtering
- CDN
- rate limiting
- cloud DDoS protection
- scalable infrastructure

考试句子：

```text
DDoS attacks aim to make a service unavailable by flooding it with massive traffic from distributed sources. It mainly attacks availability, one of the three goals in the CIA triad.
```

## 27. Risk, Threat, Vulnerability

这是 Lec 08 后半部分非常容易考简答的概念。

### Threat

Threat 是可能造成损害的危险来源或事件。

例如：

- malware
- phishing
- data breach
- rogue employee
- DDoS

### Vulnerability

Vulnerability 是系统弱点。

它可能存在于：

- software
- hardware
- people
- procedures

例如：

- unpatched software
- weak password
- wrong access control
- careless employees
- zero-day vulnerability

### Risk

Risk 是 threat 利用 vulnerability 后造成损失的可能性和影响。

课件公式：

```text
Risk = Threat Probability * Vulnerability Impact
```

更自然地说：

> Risk combines the probability of a threat and the impact if it exploits a vulnerability.

考试句子：

```text
A threat is a potential danger, a vulnerability is a weakness that can be exploited, and risk is the possibility and impact of a threat exploiting a vulnerability.
```

## 28. Zero-day Vulnerability

Zero-day vulnerability 是尚未有官方修复方案的漏洞。

特点：

- 厂商可能还不知道。
- 没有 patch。
- 防御难度高。
- 攻击窗口非常危险。

考试句子：

```text
A zero-day vulnerability is a vulnerability for which no fix or patch is currently available. It is dangerous because attackers may exploit it before defenders can update the system.
```

## 29. CIA Triad

CIA 是信息安全三个核心目标：

| 目标 | 含义 | 例子 |
|---|---|---|
| Confidentiality | 保密性 | Eve 不能读到用户密码 |
| Integrity | 完整性 | 订单金额不能被篡改 |
| Availability | 可用性 | 网站不能被 DDoS 打挂 |

不要和美国 CIA 混。

考试很可能让你用 CIA 分析攻击。

例如：

- 数据泄露：Confidentiality 受损。
- 篡改订单：Integrity 受损。
- DDoS：Availability 受损。

安全还包括：

防火墙、杀毒软件、TLS 证书都不是万能的。

## 31. Network Security Level Protection

课件提到等级保护，核心观点不是背每一级长定义，而是理解：

> There is no absolute security. Organizations should make enough and appropriate investment according to the value and risk of their assets.

也就是：

- 资产越重要，保护等级越高。
- 风险越大，投入越多。
- 不能所有系统都用同一标准。
- 安全目标是 good enough，而不是 absolute safe。

考试句子：

```text
There is no absolute security. A system should apply appropriate security controls according to its asset value, threat probability and potential impact. The goal is to manage risk to an acceptable level.
```

## 32. Vulnerability Assessment 和 Penetration Testing

### Vulnerability Assessment

Vulnerability assessment 是扫描和识别系统中已知弱点。

更像：

- 找问题。
- 列清单。
- 评估严重性。

### Penetration Testing

Penetration testing 是模拟攻击者尝试入侵系统。

更像：

- 验证漏洞是否可利用。
- 测试真实攻击路径。
- 检查防御是否有效。

考试句子：

```text
Vulnerability assessment identifies and evaluates possible weaknesses in a system, while penetration testing simulates real attacks to test whether these weaknesses can actually be exploited.
```

## 34. 最容易混的点

### Encoding vs Encryption

Encoding:

- no secret key
- reversible by public rule
- for representation

Encryption:

- uses key
- for confidentiality
- only authorized party can decrypt

### Hash vs Encryption

Hash:

- one-way
- no decryption
- used for integrity and password storage

Encryption:

- reversible with key
- used for confidentiality

### Certificate vs Public Key

Public key 是一串 key。

Certificate 是由 CA 签名的文件，用来证明：

> this public key belongs to this identity.

### Authentication vs Authorization

Authentication:

> Who are you?

Authorization:

> What are you allowed to do?

Password 常用于 authentication。

Access control 常用于 authorization。

### TLS vs HTTPS

TLS 是安全传输协议。

HTTPS 是 HTTP over TLS。

TLS 也可以保护 FTP、SMTP 等协议。

## 35. 期末答题模板

### Why is Base64 not encryption?

```text
Base64 is an encoding method, not encryption. It only changes the representation of data and does not use a secret key. Anyone who knows the Base64 rule can decode it, so it does not provide confidentiality.
```

### How does HTTPS use symmetric and asymmetric cryptography?

```text
HTTPS uses TLS to combine asymmetric and symmetric cryptography. Asymmetric cryptography and certificates are used to authenticate the server and establish a session key. After the session key is generated, symmetric encryption is used to protect the actual data transmission because it is faster.
```

### What is the role of a certificate authority?

```text
A certificate authority is a trusted third party that verifies the identity of a website or organization and signs its certificate. The certificate binds the public key to the identity. Browsers trust the certificate if it can be verified through a valid certificate chain to a trusted root CA.
```

### Why should passwords not be stored in plain text?

```text
Passwords should not be stored in plain text because if the database is leaked, attackers can directly obtain users' passwords. Instead, systems should store password hashes, preferably with salt. During login, the entered password is hashed and compared with the stored hash.
```

### What is salt and why is it useful?

```text
Salt is random data added to a password before hashing. It makes the same password produce different hash values for different users and makes rainbow table attacks much harder.
```

### Threat, vulnerability and risk

```text
A threat is a potential danger, such as malware or phishing. A vulnerability is a weakness in hardware, software, people or procedures. Risk is the probability and impact of a threat exploiting a vulnerability.
```

### CIA triad

```text
The CIA triad includes confidentiality, integrity and availability. Confidentiality means preventing unauthorized access to information, integrity means preventing unauthorized modification, and availability means ensuring services and data are accessible when needed.
```
