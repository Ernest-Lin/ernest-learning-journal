## 2. PPT 3-5: 为什么需要密码学

PPT 从 cyber attacks 开始，是为了说明电子商务不只是“网页能打开”，还要保证通信安全。

HTTP 的问题：

- HTTP 没有加密。
- HTTP message 是 plain text。
- TCP/IP packets 会经过很多中间节点。
- 中间节点理论上可以看到 packet 内容。
- 攻击者可能窃听、篡改、伪装。

电子商务里这很危险：

- 登录账号密码可能泄露。
- 订单信息可能泄露。
- 支付信息可能泄露。
- 商品价格、收货地址、购物车内容可能被篡改。

考试可以这样写：

```text
HTTP is not encrypted. Messages are transmitted in plain text, and packets may pass through many intermediate nodes. These nodes or attackers may read or modify the content. Therefore, e-commerce systems need HTTPS and cryptography to protect confidentiality, integrity and authentication.
```

## 3. HTTPS 要解决的三个安全目标

PPT 说 HTTPS 是给 HTTP 加锁。更精确地说，HTTPS/TLS 组合了多种密码学技术。

HTTPS 主要解决：

| 目标 | 英文 | 含义 |
|---|---|---|
| 保密性 | Confidentiality | Eve 看不到明文 |
| 完整性 | Integrity | 消息不能被悄悄篡改 |
| 身份认证 | Authentication | 用户知道自己连到的是真网站 |

注意：

- Encryption 主要解决 confidentiality。
- Hash 主要帮助 integrity。
- Digital signature / certificate 主要帮助 authentication。
- DH 主要帮助生成 session key。
- Symmetric encryption 主要负责后续大量数据传输。

考试里如果问 HTTPS 为什么安全，不能只写“because it encrypts data”。更好的答案是：

```text
HTTPS uses cryptography to provide confidentiality, integrity and authentication. It normally uses asymmetric cryptography and certificates to authenticate the server and exchange keys, then uses symmetric encryption to protect bulk data transfer, and uses hash/MAC mechanisms to detect tampering.
```

## 4. PPT 6-9: 密码学四件事

PPT 把 cryptography 分成四块：

- Encryption / Decryption。
- Key exchange。
- Hash functions。
- Digital signature。

三个人物：

- Alice：通信的一方，常作为发送方。
- Bob：通信的另一方，常作为接收方。
- Eve：窃听者或篡改者。

核心术语：

| 术语 | 含义 |
|---|---|
| Plaintext | 原始可读信息 |
| Ciphertext | 加密后的不可读信息 |
| Key | 加密、解密、签名或生成共享秘密时使用的密钥 |
| Encryption | 明文变密文 |
| Decryption | 密文变明文 |
| Algorithm | 加密算法，通常可以公开 |

非常重要的一句话：

> 现代密码学一般假设 algorithm 可以公开，真正需要保护的是 key。

所以如果考试问“为什么算法公开也可以安全”，可以写：

```text
Modern cryptography does not rely on hiding the algorithm. The algorithm can be public, while the security relies on the secrecy and strength of the key. Without the correct key, it should be computationally infeasible to recover the plaintext.
```

## 5. PPT 10-12: 古典密码的意义

PPT 举了 Scytale、方言、简单化学式等例子。这些不是为了让你背历史，而是让你理解加密的本质。

加密的本质：

> 即使 Eve 看到了消息，也应该看不懂。

Scytale 的 key 是棍子的尺寸或绕法。方言的 key 可以理解为只有通信双方懂的语言系统。

考试一般不会要求细算 Scytale，但可能会问 encryption 的定义：

```text
Encryption is the process of scrambling readable text into unreadable ciphertext so that only someone with the correct secret key or decryption key can recover the original message.
```

## 6. PPT 13-14: Caesar Cipher

Caesar cipher 是最简单的移位密码。

字母编号：

```text
A = 0, B = 1, C = 2, ..., Z = 25
```

加密公式：

```text
C = (P + K) mod 26
```

解密公式：

```text
P = (C - K) mod 26
```

例子：

```text
Plaintext: A
Key: 3
Ciphertext: D
```

因为：

```text
A = 0
(0 + 3) mod 26 = 3 = D
```

Caesar 为什么容易破解：

- 只有 26 种 key。
- 可以 brute force。
- 可以用 frequency analysis。

考试重点：

> Caesar 是 Vigenere 的基础。Vigenere 可以看成每个字母使用不同 Caesar key。

## 7. PPT 15-17: Vigenere Cipher

Vigenere 是往年题已经考过的内容，非常重要。

它的思想：

> 用 key word 的每个字母决定每个 plaintext 字母移动多少位。

如果 key 不够长，就循环重复。

### 7.1 Vigenere 加密公式

```text
C = (P + K) mod 26
```

其中：

- `P` 是 plaintext 字母编号。
- `K` 是 key 字母编号。
- `C` 是 ciphertext 字母编号。

例子：

```text
Plaintext:  H E L L O W O R L D
Key:        C A N S A T C A N S
Ciphertext: J E Y D O P Q R Y V
```

所以：

```text
HELLOWORLD + CANSAT = JEYDOPQRYV
```

### 7.2 Vigenere 解密公式

```text
P = (C - K) mod 26
```

例子：

```text
Ciphertext: K A T V V G F U Q Z
Key:        I M I S D M T I M I
Plaintext:  C O L D S U M M E R
```

所以：

```text
KATVVGFUQZ - IMISDMTIMI = COLDSUMMER
```

### 7.3 用 PPT 附录表做 Vigenere

附录表通常是：

- 横向 top row 是 plaintext 字母。
- 纵向 left column 是 key 字母。
- 交叉点是 ciphertext 字母。

加密时：

```text
找 key 所在行，找 plaintext 所在列，交叉点就是 ciphertext。
```

解密时：

```text
找 key 所在行，在这一行找到 ciphertext，该列顶部字母就是 plaintext。
```

### 7.4 Vigenere 为什么仍然可能被破解

PPT 说 repeatable results can be used as a weak。

意思是：

- 如果 key 反复循环，密文会出现周期性规律。
- 攻击者可以利用重复模式推测 key length。
- key 越短、重复越多，越不安全。

考试写法：

```text
Vigenere is stronger than Caesar because different positions can use different shifts. However, if the key is short and repeated, the ciphertext may contain repeated patterns. These patterns can be used to infer the key length and crack the cipher.
```

## 8. PPT 18-21: Enigma 和破解

Enigma 用一组轮子自动生成不断变化的加密状态。

核心思想：

- 不同字符使用不同映射。
- key space 远大于 Caesar 和简单 Vigenere。
- 自动化生成很多 key-like transformations。

PPT 提到 Turing，是为了说明：

> 密码系统的安全性会随计算能力、数学方法、工程能力变化。

考试一般不会让你算 Enigma，但可以用作简答题观点：

```text
No cryptographic system is permanently secure. A cipher that was strong in one historical period may become breakable when new mathematical methods or computing power become available.
```

## 9. PPT 22-29: 对称加密

Symmetric encryption 指加密和解密使用同一个 shared key。

流程：

```text
Plaintext + shared key -> Ciphertext
Ciphertext + same shared key -> Plaintext
```

优点：

- 快。
- 适合大量数据。
- 现代 CPU 常对 AES 有硬件优化。

缺点：

- Alice 和 Bob 必须先安全共享 key。
- 如果 key 被 Eve 拿到，通信就不安全。
- 用户很多时 key management 复杂。

考试常见问法：

```text
Which is typically faster: symmetric encryption or asymmetric encryption?
```

标准答案：

```text
Symmetric encryption is typically faster because it uses one shared key and simpler mathematical operations. It is suitable for encrypting large amounts of data. Asymmetric encryption relies on public/private key pairs and heavier operations such as modular exponentiation or elliptic curve operations, so it is slower.
```

## 10. DES、3DES 和 AES

### DES

DES 是 Data Encryption Standard。

PPT 要点：

- 早期重要的 block cipher standard。
- key length 太短。
- 现代计算能力下可以 brute force。
- 今天不再被认为安全。

考试句子：

```text
DES is no longer secure mainly because its key length is too short for modern brute-force attacks.
```

### 3DES

3DES 的思想：

```text
Do DES three times.
```

它比 DES 强，但不是最终理想方案：

- 计算慢。
- 设计较旧。
- 后来被 AES 替代。

### AES

AES 是 Advanced Encryption Standard。

PPT 要点：

- 由 Rijndael 发展而来。
- 用来替代 DES。
- 是现代主流对称加密算法。
- 快、安全、应用广。
- 现代 CPU 有 AES hardware optimization。

考试句子：

```text
AES replaced DES because DES became insecure due to its short key length. AES provides stronger security and better performance, and it is widely used in modern systems.
```

## 11. Block Cipher 和 Modes

PPT 说：

> Normally the data length is longer than the key. The data need to be put in blocks.

Block cipher 的意思：

- 把长数据切成固定长度的 blocks。
- 对每个 block 做加密。
- 再组合成完整 ciphertext。

### ECB

ECB 是最简单的 mode。

问题：

```text
Same plaintext block + same key -> same ciphertext block
```

所以会泄露数据模式。

考试可以这样写：

```text
ECB is simple but often not secure enough because identical plaintext blocks produce identical ciphertext blocks. This may reveal patterns in the original data.
```

### CBC、CFB、OFB、CTR

这些 mode 的共同目的：

- 减少模式泄露。
- 让相同 plaintext block 在不同位置不一定产生相同 ciphertext。
- 适应不同场景对性能、并行化、错误传播的要求。

PPT 说没有简单绝对好坏：

```text
There is no simply good or bad mode. The choice depends on the application.
```

- SM4：similar to AES。
- SM7：对称算法。
- ZUC：序列密码，移动通信中常见。

考试一般不会深挖算法细节。


## 13. PPT 30: 对称加密最大问题

PPT 问：

> How to exchange the key safely?

这是对称加密的最大问题。

如果 Alice 直接把 shared key 发给 Bob：

- Eve 可能看到 key。
- Eve 之后可以解密所有消息。
- 所以必须先解决 key exchange。

这就是 DH 和非对称密码出现的原因。

一句话：

> Symmetric encryption is fast, but sharing the symmetric key securely is difficult.

## 14. PPT 31-32: 非对称算法的数学基础

PPT 讲了一个模运算性质：

```text
a^b % p = [(a % p)^b] % p
```

这个性质的意义：

- 指数非常大时，可以每一步都取模。
- 数字不会无限变大。
- DH 和 RSA 都依赖 modular exponentiation。

考试不太可能要求完整证明，但你要会用它计算。

### 14.1 模幂手算方法

核心方法是 repeated squaring。

例子：

```text
6^13 mod 151
```

先把指数拆成二进制和：

```text
13 = 8 + 4 + 1
```

然后计算：

```text
6^2 mod 151 = 36
6^4 mod 151 = 36^2 mod 151 = 1296 mod 151 = 88
6^8 mod 151 = 88^2 mod 151 = 7744 mod 151 = 43
```

组合：

```text
6^13 mod 151 = 6^8 * 6^4 * 6^1 mod 151
              = 43 * 88 * 6 mod 151
              = 54
```

考试如果允许计算器，直接算也可以。但你必须知道公式和过程。

## 15. PPT 33-36: Diffie-Hellman Key Exchange

DH 的目的：

> Alice 和 Bob 在公开网络上生成同一个 shared session key。

公开参数：

```text
p = prime number
g = primitive root / generator
```

私有参数：

```text
Alice private key = a
Bob private key = b
```

公开值：

```text
Alice public key A = g^a mod p
Bob public key B = g^b mod p
```

session key：

```text
Alice computes: K = B^a mod p
Bob computes:   K = A^b mod p
```

因为：

```text
B^a mod p = (g^b)^a mod p = g^(ab) mod p
A^b mod p = (g^a)^b mod p = g^(ab) mod p
```

所以两边得到同一个 K。

### 15.1 DH 考试模板

```text
Given p = __, g = __, private key = __.
The D-H public key is:
A = g^a mod p = __^__ mod __ = __.
```

session key 模板：

```text
Given the other party's public key A/B = __ and my private key = __.
Session key K = (other public key)^(my private key) mod p
              = __^__ mod __ = __.
```

### 15.2 DH 的安全基础

Eve 能看到：

```text
p, g, A, B
```

Eve 不知道：

```text
a, b, K
```

要从 `g^a mod p` 推回 `a` 很难。这叫 discrete logarithm problem。

### 15.3 DH 的最大局限

PPT 36 说：

> Only by D-H algorithm, NO way to make sure the public key is really from Alice or Bob.

意思是：

- DH 可以生成 shared key。
- DH 不能证明对方身份。
- Eve 可以把自己的 DH public key 替换掉 Alice 或 Bob 的 public key。
- 这就是 man-in-the-middle attack。

考试答案：

```text
D-H can establish a shared session key, but it does not authenticate the identity of the sender. A received D-H public value may be replaced by an attacker, so D-H alone is vulnerable to man-in-the-middle attacks. It must be combined with digital signatures or certificates.
```

## 16. PPT 37-42: RSA

RSA 是非对称算法。

RSA key pair：

```text
Public key:  (e, N)
Private key: (d, N)
```

PPT 的核心条件：

```text
g^(de) mod N = g
```

### 16.1 RSA 加密方向

别人想给 Alice 发秘密消息，就用 Alice 的 public key 加密。

```text
C = M^e mod N
M = C^d mod N
```

方向：

```text
Encrypt with public key.
Decrypt with private key.
```

用途：

```text
Confidentiality
```

### 16.2 RSA 签名方向

Alice 想证明消息来自自己，就用 Alice 的 private key 签名。

```text
S = M^d mod N
M' = S^e mod N
```

方向：

```text
Sign with private key.
Verify with public key.
```

用途：

```text
Authentication + integrity
```

这是考试最容易混的点。

### 16.3 RSA key generation 基本逻辑

PPT 给了 Euler totient：

```text
N = m * n
φ(N) = (m - 1)(n - 1)
de = kφ(N) + 1
```

其中 `m` 和 `n` 是两个素数。

RSA 难破解的原因：

- 已知 `m` 和 `n`，算 `N` 很容易。
- 只知道很大的 `N`，分解出 `m` 和 `n` 很难。
- 如果能分解 `N`，就能算 `φ(N)`，进一步推出 private key。

考试句子：

```text
RSA security relies on the difficulty of factoring a large integer N into its two prime factors. If N can be factorized, the private key can be derived.
```

### 16.4 PPT RSA 示例

PPT 例子：

```text
m = 29
n = 83
N = 29 * 83 = 2407
φ(N) = (29 - 1)(83 - 1) = 2296
e = 5
k = 4
d = (4 * 2296 + 1) / 5 = 1837
```

key pair：

```text
Public key:  (5, 2407)
Private key: (1837, 2407)
```

加密：

```text
C = 199^5 mod 2407 = 1557
```

解密：

```text
M = 1557^1837 mod 2407 = 199
```

## 17. RSA + DH 组合题

两套期末都在考这个组合。

场景：

- Alice 和 Bob 要建立 secure communication channel。
- DH 用来生成 session key。
- RSA 用来签名或验签，保证 DH public key 没有被篡改。

### 17.1 为什么要组合

只用 DH：

- 可以生成 session key。
- 不能确认收到的 DH public key 真的是 Alice 或 Bob 的。

加入 RSA signature：

- 发送方用 private key 签自己的 DH public key。
- 接收方用发送方 public key 验证签名。
- 如果验签通过，说明这个 DH public key 没被替换。

一句话：

> DH gives the shared key, RSA signature gives authentication.

### 17.2 生成 DH public key + RSA signature

题型：

```text
Bob private key for D-H = b
p = __
g = __
Bob RSA private key = (d, N)
```

Step 1: 算 Bob DH public key。

```text
B = g^b mod p
```

Step 2: 用 Bob RSA private key 对 `B` 签名。

```text
S = B^d mod N
```

Bob 发给 Alice：

```text
D-H public key = B
RSA signature = S
```

### 17.3 验证对方发来的 DH public key

题型：

```text
Received D-H key = M
Received RSA signature = S
Sender public key = (e, N)
```

Step 1: 用发送方 public key 验签。

```text
M' = S^e mod N
```

Step 2: 比较。

```text
If M' == M, signature is valid.
If M' != M, the key/signature was tampered with.
```

### 17.4 验签后算 session key

只有验签有效的 DH public key 才能用于 session key。

如果 Bob 收到 Alice 的有效 DH public key `A`，Bob 私钥是 `b`：

```text
K = A^b mod p
```

如果 Alice 收到 Bob 的有效 DH public key `B`，Alice 私钥是 `a`：

```text
K = B^a mod p
```

## 18. Past Paper 1 精讲

题目数据：

```text
Alice RSA public:  (7, 299)
Alice RSA private: (151, 299)

Bob RSA public:    (7, 119)
Bob RSA private:   (55, 119)

D-H p = 151
D-H g = 6
Bob D-H private key = 13
```

### 18.1 Bob 的 DH public key

公式：

```text
B = g^b mod p
```

代入：

```text
B = 6^13 mod 151 = 54
```

所以：

```text
Bob D-H public key = 54
```

### 18.2 Bob 给 DH public key 生成 RSA signature

因为是 Bob 发出的 key，所以用 Bob 的 private key。

```text
Bob private key = (55, 119)
Message M = 54
```

签名：

```text
S = M^d mod N
S = 54^55 mod 119 = 96
```

Bob 发送：

```text
D-H key = 54
RSA sign = 96
```

### 18.3 Alice 如何验证

Alice 用 Bob 的 public key 验证。

```text
Bob public key = (7, 119)
```

验证：

```text
M' = S^e mod N
M' = 96^7 mod 119 = 54
```

比较：

```text
54 == received D-H key 54
```

所以签名有效。

答题句：

```text
Alice verifies the signature using Bob's public key. If the recovered value equals the received D-H public key, the originality and integrity of the key are verified.
```

循环 key：

```text
Ciphertext: K A T V V G F U Q Z
```

## 19. Past Paper 2 精讲

题目数据：

```text
Alice RSA public:  (7, 187)
Alice RSA private: (23, 187)

Bob RSA public:    (7, 247)
Bob RSA private:   (31, 247)

D-H p = 227
D-H g = 8
```

### 19.1 验证两个 Alice DH public keys

Bob 收到两个候选：

```text
[D-H key: 92, RSA sign: 9]
[D-H key: 15, RSA sign: 42]
```

因为这些 key 声称来自 Alice，所以 Bob 用 Alice 的 public key 验证。

Alice public key：

```text
(e, N) = (7, 187)
```

候选 1：

```text
M' = 9^7 mod 187 = 70
70 != 92
```

所以候选 1 无效。

候选 2：

```text
M' = 42^7 mod 187 = 15
15 == 15
```

所以有效 key 是：

```text
[D-H key: 15, RSA sign: 42]
```

## 20. PPT 43-46: 数字签名

PPT 说传统签名图片很 fragile。

原因：

- 签名图片可以复制。
- 图片不能证明文件内容没改。
- 图片不能和具体数据强绑定。
- 截图或贴图很容易伪造。

Digital signature 的目标：

- Authentication：证明是谁签的。
- Integrity：证明内容没改。
- Non-repudiation：签名者之后难以否认。

RSA digital signature：

```text
Sign:   S = M^d mod N
Verify: M = S^e mod N
```

考试关键：

> RSA can be used for authentication because only the private key holder can generate a valid signature, and everyone can verify it using the public key.

## 21. PPT 47-54: Hash

Hash 是 message digest。

定义：

```text
A hash function converts an input of arbitrary length into a fixed-length output.
```

Hash 的性质：

- One-way：不能从 hash decode 回原文。
- Fixed length：输出长度固定。
- Avalanche effect：原文小变化导致 hash 大变化。
- Collision resistance：很难找到两个不同输入有同样 hash。

注意：

> Hash is not encryption.

区别：

| 项目 | Encryption | Hash |
|---|---|---|
| 能否还原 | 可以 decrypt | 设计上不能还原 |
| 是否需要 key | 通常需要 key | 普通 hash 不需要 key |
| 输出长度 | 和明文/模式有关 | 固定长度 |
| 主要用途 | 保密 | 完整性摘要 |

### 21.1 MD5 和 SHA

PPT 提到 MD5 和 SHA。

MD5：

- 曾经广泛使用。
- 现在不适合安全场景。
- 原因是 collision attack。

SHA：

- 更常用于现代安全场景。
- 常见 SHA-256、SHA-384、SHA-512。

### 21.2 Hash 用于完整性校验

例子：

```text
Official website publishes:
file.zip
SHA-256 = abc...
```

用户下载后计算本地 hash：

- 如果相同，文件大概率没被改。
- 如果不同，文件损坏或被篡改。

考试句子：

```text
Hash functions are widely used to verify integrity. The receiver calculates the hash value of the received data and compares it with the published or signed hash value. If they differ, the data has been modified.
```

## 22. 为什么数字签名通常签 Hash

PPT 53 说：

> Only need to sign the HASH but not the full text.

原因：

- 原文可能很大。
- RSA 计算慢。
- hash 固定长度，签起来更高效。
- 原文任何变化都会导致 hash 改变。

实际签名流程：

```text
Message -> Hash -> Sign hash with private key -> Signature
```

验证流程：

```text
Received message -> Hash again
Signature -> Verify with public key -> Get signed hash
Compare the two hash values
```

考试答案：

```text
Digital signatures usually sign the hash of the message instead of the whole message because RSA is computationally expensive and the message can be large. A hash is fixed length and any change in the message changes the hash, so signing the hash is efficient and still protects integrity.
```

## 23. PPT 55-58: ECC 和 SM2

考试句子：

```text
ECC can achieve a similar security level with a shorter key than RSA, so it is often faster and more efficient. SM2 is a Chinese asymmetric cryptographic algorithm based on ECC.
```

## 24. PPT 59-60: 算法成本与安全比较

PPT 说：

```text
The security of different algorithms cannot be compared directly only by key length, because they rely on different mathematical problems. A fair comparison should consider the computational cost required to break them.
```

```text
In real systems, asymmetric encryption is used for authentication and key exchange, while symmetric encryption is used for bulk data transfer. This combines the advantages of both.
```

## 25. PPT 61-63: 量子计算和后量子密码

PPT 提到 Shor algorithm。

核心：

- Shor algorithm 可以高效分解大整数。
- RSA 依赖大整数分解困难。
- 如果强量子计算机成熟，RSA 会受到严重威胁。

Post-quantum cryptography：

- 目标是在量子计算时代仍然安全。
- PPT 提到 lattice encryption。

Quantum key：

- 量子技术既可能攻击传统密码，也可能用于新的密钥分发方式。

考试简答：

```text
Quantum computing threatens RSA because Shor's algorithm can factor large integers efficiently, while RSA security relies on the difficulty of factoring N. Post-quantum cryptography tries to design algorithms that remain secure even against quantum computers.
```

## 26. 最重要公式总表

```text

```


```text

B = g^b mod p

```

### RSA encryption

```text

```

```text
S = M^d mod N
M' = S^e mod N
Valid if M' == M
```


## 27. 最重要英文答题模板

### Why is HTTP insecure?

```text
HTTP is insecure because it transmits messages in plain text. Packets pass through intermediate nodes, and attackers may read or modify their content. Therefore, e-commerce systems need HTTPS and cryptography to protect confidentiality, integrity and authentication.
```

### Symmetric vs asymmetric speed

```text
Symmetric encryption is typically faster because it uses one shared key and simpler operations. Asymmetric encryption uses public/private key pairs and heavier mathematical operations, so it is slower. In practice, asymmetric cryptography is used for key exchange or digital signatures, and symmetric encryption is used for bulk data.
```

### Why can RSA authenticate but DH cannot?

```text
RSA can provide authentication because it supports digital signatures. The sender signs data with the private key, and others verify it with the public key. Only the private key holder can generate a valid signature. D-H only establishes a shared session key and does not prove who sent the D-H public value, so D-H alone cannot provide authentication and is vulnerable to man-in-the-middle attacks.
```

### Why sign hash instead of full message?

```text
Digital signatures usually sign the hash of a message because the message may be large and RSA is computationally expensive. The hash has a fixed length, and any change in the message changes the hash, so signing the hash is efficient and still protects integrity.
```

### Why is DES not secure now?

```text
DES is not secure in the modern world because its key length is too short and can be brute-forced with current computing power. AES is preferred because it provides stronger security and better performance.
```

## 28. 最容易丢分的点

- Vigenere 加密是加 key。
- Vigenere 解密是减 key。
- Hash 不能 decrypt。
- DH 本身不能 authentication。
- RSA 可以 authentication 是因为 digital signature。
- Symmetric encryption 比 asymmetric encryption 快。
