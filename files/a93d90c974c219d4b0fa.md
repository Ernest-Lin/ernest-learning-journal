# CAN302 简答题重点复习

整理依据：你发的几张 Problem II 简答题截图，以及本地 Lec 05-12 课件/笔记。重点不是逐题背答案，而是把反复考的主题变成可套用的答题框架。

## 0. 出题规律

Problem II 的简答题常见套路：

- 先给一个判断句：`Do you agree/disagree... Give your reasons.`
- 每题通常 5-6 分，要求短、准、相关。
- 高频主题集中在：E-commerce/EDI、SEO、MVC/API、Load balancing、Cryptography/HTTPS、Digital evidence、Testing。

建议答题格式：

```text
I agree/disagree with the statement.
First, define the key concept.
Then give 2-3 technical reasons.
Finally mention a limitation or real system practice.
```

## 1. E-commerce / Web Commerce / EDI

### 1.1 三种 flow in commerce

必背：

- Information flow：商品信息、搜索、订单、发票、客服。
- Money/Fund flow：付款、退款、结算、转账。
- Goods/Logistics flow：仓储、运输、配送、交付。

哪些可以 fully electronic：

- 信息流可以完全电子化。
- 资金流可以通过电子支付/EFT/信用卡网络完全电子化。
- 商品流只有在数字商品或服务中可以完全电子化；实体商品仍需要物流。

考场句：

```text
The three flows are information flow, fund flow and goods flow. Information flow and fund flow can usually be fully electronic. Goods flow can be fully electronic only for digital products such as software, music or online services; for physical products it still needs physical logistics.
```

### 1.2 E-commerce vs Web/Internet commerce

必背：

- E-commerce：由电子技术支持的商业交易，范围更广。
- Web/Internet commerce：通过 Web/Internet 完成的商务，范围更窄。
- 所以：所有 Web commerce 通常属于 E-commerce，但 E-commerce 不一定都是 Web commerce。

### 1.3 EDI 是否属于 Web Commerce / E-commerce

结论：

- EDI 属于 E-commerce，因为它用标准电子格式交换商业文件。
- 传统 EDI 不一定属于 Web commerce，因为它可以通过 VAN、AS2、FTP/VPN 等方式，不一定用 Web。
- Web EDI 才可以算 Web commerce 的一种实现。

考场句：

```text
EDI belongs to e-commerce because it uses electronic technology and standard formats to exchange business documents such as purchase orders and invoices. However, traditional EDI does not necessarily belong to web commerce, because it may use VAN, AS2 or FTP/VPN instead of the Web. Only Web EDI can be regarded as web commerce.
```

### 1.4 EDI 是否适合 B2C

结论：通常不适合。

原因：

- EDI 面向企业间长期、重复、大批量、标准化交易。
- 设置成本高，需要双方系统和标准对接。
- B2C 用户数量大、交易零散、需求变化快，更适合 Web/App 界面。

考场句：

```text
EDI is usually not suitable for B2C applications. It is designed for B2B transactions where companies repeatedly exchange standardized documents. It has high setup cost and requires system integration. B2C customers need flexible web or mobile interfaces, so ordinary e-commerce websites are more suitable.
```

### 1.5 Internet e-commerce 是否让 EDI 不再使用

结论：不同意。

原因：

- Internet commerce 发展很快，但 EDI 在供应链、采购、物流、发票等 B2B 场景仍常用。
- 企业需要可靠、标准化、自动化的商业文件交换。
- 现代 EDI 可以结合 Internet 技术，例如 AS2、Web EDI、FTP/VPN。

## 2. SEO / Search Engine / SEM

### 2.1 Search engine 三步

必背三步：

1. Crawling：爬虫发现网页，跟随链接抓取内容。
2. Indexing：分析网页内容，建立倒排索引。
3. Ranking/Serving：根据相关性、质量、链接、用户体验等排序并返回结果。

考场句：

```text
A search engine works in three main steps: crawling, indexing and ranking. Crawlers discover pages through hyperlinks. The system analyzes the pages and builds an inverted index. When a user searches, the engine ranks relevant pages and serves the results.
```

### 2.2 什么是 SEO

定义：

SEO = Search Engine Optimization。通过优化网站内容、结构、速度、链接和用户体验，提高网页在 organic listings 中的排名。

三条常用 tips：

- 做 keyword research，匹配用户搜索意图。
- 写高质量、相关、结构清楚的内容。
- 优化页面速度、移动端适配、URL、图片 alt text、internal links。
- 获取高质量 backlinks。

考场句：

```text
SEO is Search Engine Optimization. It aims to improve a website's ranking in organic search results. Useful SEO methods include keyword research, high-quality and relevant content, fast loading speed, mobile-friendly design, clear URL structure, internal links and high-quality backlinks.
```

### 2.3 Backlinks 的作用

结论：

- Backlink 是其他网站指向你网站的链接，像外部推荐。
- 它能帮助搜索引擎判断网页权威性、可信度和重要性。
- 不是所有 backlinks 都同样有价值。

高价值 backlink：

- 来自权威网站。
- 与主题相关。
- 真实自然，不是垃圾链接。
- anchor text 合理。

低价值/有害 backlink：

- spam site、link farm、不相关网站、付费垃圾链接。

考场句：

```text
Backlinks are important in SEO because they work like recommendations from other websites and help search engines estimate authority and trust. However, not all backlinks are equally valuable. Links from authoritative and relevant websites are much more useful than links from spam, irrelevant or low-quality sites.
```

### 2.4 Paid listings vs Organic listings

必背：

- Paid listings：付费广告结果，属于 SEM，见效快，但停止付费流量会下降。
- Organic listings：自然搜索结果，靠 SEO 排名，不按点击直接付费，见效慢但长期价值高。

考场句：

```text
Paid listings are search results displayed because advertisers pay for them. They can bring traffic quickly but cost money and usually disappear when payment stops. Organic listings are natural search results ranked by relevance and quality. They are improved by SEO and usually have better long-term value.
```

## 3. Load Balancing / Nginx / LVS / MySQL

### 3.1 DNS 能不能用于 load balance

结论：可以，但比较粗。

原因：

- DNS 可以返回多个 IP，或按地区/轮询返回不同服务器地址。
- 可以分散访问流量。
- 但 DNS 不太适合精细实时控制，因为 TTL 缓存、健康检查弱、会话保持困难。

考场句：

```text
DNS can be used for load balancing by returning different IP addresses for the same domain, for example round-robin or geo-based DNS. However, it is a coarse method. Because of DNS caching and TTL, it cannot react quickly to server failure and cannot easily control sessions or real-time server load.
```

### 3.2 Nginx 与 LVS 的区别

必背：

- Nginx：主要是 HTTP/Layer 7 反向代理和负载均衡，可按 URL、header、静态资源等规则处理。
- LVS：Linux Virtual Server，工作在网络/传输层，主要处理 TCP/UDP 包，性能更强但不理解 HTTP 业务内容。

考场句：

```text
Nginx and LVS work at different levels. Nginx mainly works as an HTTP or layer-7 reverse proxy, so it can route requests based on URL or HTTP information. LVS works at layer 4 and forwards TCP/UDP packets, so it is usually faster and has stronger raw load capacity, but it cannot understand application-level HTTP rules.
```

### 3.3 “LVS has stronger load capacity than Nginx”

结论：基本同意，但要说明侧重点不同。

原因：

- LVS 在内核/网络层转发包，处理逻辑轻。
- Nginx 在 HTTP 层处理 request/response，功能更丰富但成本更高。
- 实际架构常把二者结合。

### 3.4 “LVS cannot be used together with Nginx”

结论：不同意。

最佳实践：

```text
User -> LVS layer-4 load balancer -> Nginx layer-7 reverse proxies -> application servers -> database
```

考场句：

```text
I disagree. LVS and Nginx can be used together. LVS can distribute traffic at layer 4 to several Nginx servers, and Nginx can then handle HTTP-level routing, static content and reverse proxy rules. This combines the high capacity of LVS with the flexibility of Nginx.
```

### 3.5 Nginx 能不能做 MySQL load balancing

建议答法：谨慎部分同意，但普通 Nginx 不适合做完整 MySQL 负载均衡。

原因：

- MySQL 是数据库协议，不是 HTTP。
- Nginx 的强项是 HTTP 反向代理。
- 即使通过 TCP stream 转发，也不能理解 SQL、事务、主从读写分离。
- 真正 MySQL 集群需要 DB proxy、应用读写分离、主从复制、keepalived/HA 等。

考场句：

```text
Nginx can proxy TCP traffic in some configurations, so it may distribute simple MySQL connections. However, it is not a complete MySQL load-balancing solution because it does not understand SQL semantics, transactions or read/write splitting. Real MySQL load balancing usually needs a database proxy, master/slave replication, application logic and high-availability design.
```

## 4. MVC / Zend / XAMPP / Front-end Back-end Split

### 4.1 MVC 三部分

必背：

- Model：数据和业务逻辑，可能包含 DAL/database interaction。
- View：展示层，生成用户看到的界面或结果。
- Controller：接收请求，调用 Model，选择 View，返回响应。

### 4.2 Web MVC 能不能避免 router

结论：不同意。

原因：

- Router 把 URL 映射到 controller/action。
- MVC 框架通常不直接按文件路径访问 controller。
- 没有 router 就很难组织复杂 URL、模块和参数。

考场句：

```text
I disagree. A web MVC solution normally needs a router. The router maps a URL to a controller and an action, and may also extract parameters from the URL. Without routing, the system would fall back to simple file-path mapping, which is not suitable for a maintainable MVC application.
```

### 4.3 Zend MVC HTTP request 处理流程

考场流程：

```text
Browser sends HTTP request
-> Apache receives it
-> dynamic request goes to public/index.php
-> router matches URL to module/controller/action
-> controller reads parameters
-> controller calls model/business logic/database
-> view renders HTML
-> PHP/Apache sends HTTP response
-> browser renders the page
```

考场句：

```text
In a Zend MVC application, Apache receives the HTTP request and dynamic requests normally enter public/index.php. The router maps the URL to a module, controller and action. The controller gets parameters, calls the model or database logic, and passes data to the view. The view renders HTML, then PHP and Apache return the HTTP response to the browser.
```

### 4.4 XAMPP stack HTTP request 处理流程

考场流程：

```text
Browser request
-> Apache web server
-> static file directly returned, or PHP script executed
-> PHP may query MySQL
-> PHP generates HTML/JSON
-> Apache returns response
-> browser renders result
```

考场句：

```text
In a XAMPP stack, the browser sends an HTTP request to Apache. If the request is for a static file, Apache returns it directly. If it is for a PHP script, Apache invokes PHP to execute server-side code. PHP may access the MySQL database, generate HTML or JSON, and Apache sends the response back to the browser.
```

### 4.5 前后端分离后，前端 HTML 是否仍是后端 View

结论：通常不同意。

原因：

- 前后端分离意味着前端和后端是两个独立系统。
- 后端主要通过 API 返回 JSON。
- JSON 可以看作后端 MVC 的 View，也可以作为前端的 Model。
- 前端 HTML/component 才是前端系统自己的 View。

考场句：

```text
I disagree in a strict front-end and back-end split. The front-end and back-end become two independent systems. The back-end usually returns JSON through APIs, and this JSON can be regarded as the view of the back-end and the model of the front-end. The HTML page or front-end component is the view of the front-end system, not simply the view of the back-end.
```

## 5. Cryptography / HTTPS / RSA / DH

### 5.1 Symmetric encryption vs Asymmetric encryption 哪个更快

结论：对称加密更快。

原因：

- 对称加密使用一个 shared key，运算较简单。
- 非对称加密使用 public/private key pair，涉及更重的数学运算。
- 实际系统中：非对称用于认证/密钥交换，对称用于大量数据传输。

考场句：

```text
Symmetric encryption is typically faster. It uses one shared key and simpler operations, so it is efficient for bulk data encryption. Asymmetric encryption uses a public/private key pair and heavier mathematical operations, so it is slower. In practice, asymmetric cryptography is used for authentication or key exchange, and symmetric encryption is used for bulk data.
```

### 5.2 HTTPS 是否用非对称算法加密所有数据

结论：不同意。

原因：

- HTTPS/TLS 组合多种算法。
- 非对称加密/证书用于服务器认证和建立 session key。
- 后续大量数据用对称加密。
- Hash/MAC/HMAC 用于完整性检测。

考场句：

```text
I disagree. HTTPS does not use asymmetric algorithms to encrypt all data. TLS uses certificates and asymmetric cryptography to authenticate the server and establish a session key. After the session key is generated, symmetric encryption is used for bulk data transmission because it is much faster. Hash or MAC mechanisms are used to protect integrity.
```

### 5.3 为什么 RSA 可用于 authentication，但 DH 不行

结论：

- RSA 可以做 digital signature。
- 私钥签名，公钥验证；只有私钥持有者能产生有效签名。
- DH 只是让双方生成 shared secret，不证明对方身份。
- 单独 DH 容易被 man-in-the-middle attack。

考场句：

```text
RSA can provide authentication because it supports digital signatures. The sender signs data with the private key, and others verify it with the public key. Only the private key holder can generate a valid signature. D-H only establishes a shared session key and does not prove who sent the D-H public value, so D-H alone is vulnerable to man-in-the-middle attacks.
```

### 5.4 “Using only DH can safely generate a shared secret key”

结论：不同意或部分同意。

答法：

- 对 passive eavesdropper，DH 可以生成共享密钥。
- 但对 active attacker，单独 DH 不安全，因为没有身份认证。
- 需要配合 RSA signature、certificate 或其他认证机制。

## 6. Digital Evidence / Notarization / Blockchain

### 6.1 Chain of custody 为什么重要

必背：

- 记录证据从收集、保存、转移、分析到提交的全过程。
- 说明谁在什么时间接触过证据，做了什么。
- 防止篡改、污染、丢失。
- 提高证据在法院中的可信度和可采性。

考场句：

```text
Chain of custody is critical because digital evidence is fragile and can be altered or destroyed by improper handling. It records who collected, handled, transferred and stored the evidence, and when each action happened. This helps prove integrity, prevent tampering and make the evidence more credible in court.
```

### 6.2 法院是否只接受公证监督下截取的网页截图

结论：不同意。

原因：

- 公证能提高可信度，因为过程有特殊见证人监督。
- 但法院不一定只接受公证截图。
- 其他方式也可证明真实性和完整性，例如司法鉴定报告、服务器日志、时间戳、哈希、取证平台、证据保全系统等。

考场句：

```text
I disagree. Notarial preservation can greatly increase the credibility of webpage screenshots because the process is supervised by notarial officers. However, it is not the only possible effective evidence. Other evidence may also be accepted if its source, integrity, time and collection process can be proved by forensic reports, logs, timestamps or other reliable preservation methods.
```

### 6.3 公证能否证明 emails 的 authenticity

结论：不能完全证明，只能增强可信度。

原因：

- 公证可以证明某时某设备/账号中看到了这封邮件，或保存过程受监督。
- 但不能自动证明邮件内容一定未被伪造，或发件人身份一定真实。
- 还需要邮件头、服务器日志、数字签名、取证鉴定等支持。

考场句：

```text
Notarization can increase the credibility of an email as evidence, but it cannot by itself fully prove the authenticity of the email. It can prove that a notarial officer observed or preserved the email at a certain time. To prove the real sender and whether the content was forged, we may still need email headers, server logs, digital signatures or forensic examination.
```

### 6.4 Blockchain 上保存的网页截图是否一定是真的

结论：不同意。

原因：

- Blockchain 能证明某数据在某时间后不容易被篡改。
- 但不能保证上传前的数据是真的。
- 如果一开始上传的是假截图，区块链只能保存这个假截图。
- 真实性还依赖取证过程、可信机构、hash、原始来源和完整 chain of custody。

考场句：

```text
I disagree. Blockchain can help prove that stored data has not been changed after it was recorded, but it cannot prove that the original screenshot was real before being uploaded. If a fake screenshot is put on the blockchain, the blockchain only preserves a fake record. Authenticity still depends on reliable collection, trusted preservation process and chain of custody.
```

## 7. Testing / Cross-browser Compatibility

### 7.1 Test plan 是否应该开发完成后再写

结论：不同意。

原因：

- 测试应从需求/设计阶段开始。
- Survey 后可写 system test cases。
- Design 后可写 unit test cases。
- Coding 开始后执行 unit test，并继续写 integration test。
- 需求变化时更新测试用例。

考场句：

```text
I disagree. The test plan should not be written only after development is completed. Testing should be considered from the design stage and should start at the beginning of coding. System test cases can be prepared after requirements, unit test cases after design, and integration test cases during module development. This helps find defects earlier and improves software quality.
```

### 7.2 后端没完成前能不能测试前端

结论：可以测试。

原因：

- 前端可以使用 mock data、stub、fake API、mock server。
- 可先测 UI、交互、布局、可用性、兼容性。
- 后端完成后再做集成测试和端到端测试。

考场句：

```text
I disagree. Front-end development can be tested before the back-end is completed. Developers can use mock data, stubs, fake APIs or mock servers to simulate back-end responses. UI layout, interaction, usability and browser compatibility can be tested first. After the back-end is ready, integration and end-to-end tests can be performed.
```

### 7.3 为什么 e-commerce solution 要测 cross-browser compatibility

必背原因：

- 不同浏览器有不同 rendering engine，例如 Blink、WebKit。
- HTML/CSS/JavaScript 可能显示或执行不同。
- 电商网站影响购买、支付、登录、购物车等关键流程。
- 兼容性问题会导致用户流失和收入损失。
- 可用 Selenium Grid 自动化测试不同 OS/browser 组合。

考场句：

```text
Cross-browser compatibility must be tested because different browsers use different rendering engines and may interpret HTML, CSS and JavaScript differently. For an e-commerce solution, display or functional problems may affect login, product pages, shopping carts and payment, causing user loss and business loss. Therefore, the site should be tested on major browser and OS combinations, often with tools such as Selenium Grid.
```

### 7.4 常见测试类型

必背：

- Functional test：功能是否正确。
- Usability test：是否好用。
- Compatibility test：多浏览器、多平台是否适配。
- Reliability test：是否稳定可靠。
- Security test：是否有漏洞。
- Performance test：是否高效、能承受流量。

## 8. B 层备选简答题

这一层不是截图里最密集出现的题，但从 Lec 01-12 的课件标题和内容看，属于老师很容易临时改成 4-6 分简答题的概念。时间紧时先背第 9 节 A 层；时间够再看这里。

### 8.1 Web page 如何工作：Client-Server + HTTP

必背：

- Browser 是 client，Web server 是 server。
- Client 发送 HTTP request。
- Server 根据 URL/path 找资源或执行程序。
- Server 返回 HTTP response，里面可能包含 HTML/CSS/JS/图片/JSON。
- Browser 解析并渲染页面。

考场句：

```text
A webpage works in a client-server model. The browser sends an HTTP request to the web server. The server finds the requested resource or executes server-side code, then returns an HTTP response. The browser receives HTML, CSS, JavaScript or other resources and renders the final webpage for the user.
```

### 8.2 URL / DNS / IP / Port

必背：

- URL 描述访问什么资源。
- DNS 把 domain name 转换成 IP address。
- IP address 定位网络中的主机。
- Port 定位主机上的具体服务，例如 HTTP 80、HTTPS 443。

考场句：

```text
A URL tells the browser which resource to access. DNS translates the domain name into an IP address. The IP address identifies the server on the network, and the port number identifies the specific service running on that server.
```

### 8.3 HTTP GET vs POST

必背：

- GET 通常用于获取资源，参数常出现在 URL 中。
- POST 通常用于提交数据，数据主要放在 request body 中。
- GET 更适合查询，POST 更适合表单提交、登录、下单等。
- 二者都不是天然安全；安全性依赖 HTTPS 等机制。

考场句：

```text
GET is mainly used to request or retrieve resources, and its parameters are often visible in the URL. POST is mainly used to submit data to the server, and the data is sent in the request body. GET is suitable for queries, while POST is more suitable for forms, login or order submission. However, neither method is secure by itself; HTTPS is still needed.
```

### 8.4 HTTP header vs HTML head

必背：

- HTTP header 是 request/response 的通信元数据。
- HTML head 是 HTML 文档的一部分，包含 title、meta、style、link 等页面信息。
- 整个 HTML 文件是 HTTP response body 的一部分。

考场句：

```text
HTTP header and HTML head are different. HTTP headers are metadata in the HTTP request or response, such as status, content type or cookies. HTML head is part of the HTML document and contains page metadata such as title, meta tags, styles and links.
```

### 8.5 HTML / CSS / JavaScript 的分工

必背：

- HTML 负责 structure/content，组织 DOM tree。
- CSS 负责 style/layout，让页面好看。
- JavaScript 负责 interactivity/dynamic behavior。

考场句：

```text
HTML structures the content of a webpage and builds the DOM tree. CSS controls the visual style and layout. JavaScript adds interactivity and dynamic behavior, such as responding to user actions or updating page content without reloading.
```

### 8.6 DOM Tree

必背：

- DOM 是 Document Object Model。
- HTML 元素被组织成树结构。
- 浏览器和 JavaScript 可以通过 DOM 读取或修改网页元素。

考场句：

```text
The DOM, or Document Object Model, represents an HTML document as a tree of elements. Each tag becomes a node in the tree. JavaScript can access and modify DOM nodes, so the page content and style can change dynamically in the browser.
```

### 8.7 Bootstrap 为什么有用

必背：

- Bootstrap 是前端框架。
- 提供 responsive grid、预制组件、样式和 JS 插件。
- 可快速做 mobile-first、响应式页面。

考场句：

```text
Bootstrap is a front-end framework that helps developers build responsive and mobile-first websites quickly. It provides a grid system, predefined CSS styles, UI components and JavaScript plugins, so developers do not need to design every component from zero.
```

### 8.8 Static webpage vs Dynamic webpage

必背：

- Static webpage：服务器直接返回固定 HTML 文件。
- Dynamic webpage：服务器执行 PHP/程序，结合数据库生成 HTML 或 JSON。
- 电商网站商品多、库存和价格变化快，所以需要动态网页。

考场句：

```text
A static webpage is a fixed HTML file returned directly by the server. A dynamic webpage is generated by server-side code, often using database data. E-commerce websites need dynamic pages because products, prices, stock and user information change frequently.
```

### 8.9 Cookie / Session 为什么需要

必背：

- HTTP 是 stateless。
- Cookie 存在 browser，可带 session id。
- Session 通常存在 server，用来保存登录状态、购物车等。

考场句：

```text
HTTP is stateless, so the server does not automatically remember previous requests. Cookies and sessions are used to maintain state. A cookie is stored in the browser and often contains a session ID, while the actual session data is stored on the server, such as login status or shopping cart data.
```

### 8.10 Base64 是否是 encryption

结论：不是。

原因：

- Base64 是 encoding，只改变表示形式。
- 没有 secret key。
- 任何人知道规则都能 decode。
- 不提供 confidentiality。

考场句：

```text
Base64 is not encryption. It is only an encoding method that converts data into another representation. It does not use a secret key, and anyone who knows the rule can decode it. Therefore, Base64 does not provide confidentiality.
```

### 8.11 Password 为什么不能明文保存

必背：

- 数据库泄露时明文密码会直接暴露。
- 用户常复用密码，会引发更大风险。
- 应保存 password hash，而不是原密码。
- Salt 可以防 rainbow table，并让相同密码产生不同 hash。

考场句：

```text
Passwords should not be stored in plain text. If the database is leaked, all user passwords will be exposed directly. A system should store salted password hashes instead. Salt makes identical passwords produce different hashes and makes rainbow table attacks much harder.
```

### 8.12 CIA Triad / Risk

必背：

- CIA = Confidentiality, Integrity, Availability。
- Confidentiality：防止未授权读取。
- Integrity：防止数据被未授权篡改。
- Availability：系统可用，不被 DDoS/故障拖垮。
- Risk 与 threat、vulnerability、impact 有关。

考场句：

```text
The CIA triad includes confidentiality, integrity and availability. Confidentiality prevents unauthorized access to data. Integrity ensures data is not modified without authorization. Availability ensures the system remains usable. Security risk depends on threats, vulnerabilities and the possible impact.
```

### 8.13 AJAX / XML / JSON / API / REST

必背：

- AJAX 让浏览器在不刷新整个页面的情况下与后端交换数据。
- XML 和 JSON 都可表示数据；JSON 更轻、更适合 JavaScript，现代 Web 更常用。
- API 是系统之间交换信息的接口。
- REST 是基于 HTTP 资源和方法的 API 架构风格，不是新协议。

考场句：

```text
AJAX allows the browser to communicate with the server asynchronously without reloading the whole page. XML and JSON are data formats, but JSON is now more popular in web applications because it is lightweight and fits JavaScript well. An API defines how systems exchange data, and REST is an architectural style for designing HTTP APIs.
```

### 8.14 Three-layer architecture vs MVC

必背：

- Three-layer 常指 UI layer、Business Logic layer、Data Access layer。
- MVC 是 Model、View、Controller。
- 二者都用于分离关注点，但不是一一对应。
- MVC 更关注用户交互请求如何被 controller/model/view 协作处理。

考场句：

```text
Three-layer architecture and MVC are related but not the same. Three-layer architecture separates UI, business logic and data access. MVC separates an application into model, view and controller. Both improve maintainability, but they divide the system from different viewpoints and do not always map one-to-one.
```

### 8.15 CDN

必背：

- CDN = Content Delivery Network。
- 把静态资源分发到离用户更近的节点。
- 降低延迟，减轻源站压力，提高可用性。
- 主要适合图片、JS、CSS、视频等静态内容。

考场句：

```text
A CDN is a Content Delivery Network. It stores static resources on distributed servers closer to users. This reduces latency, decreases load on the origin server and improves availability. It is especially useful for images, JavaScript, CSS and videos.
```

### 8.16 SOA / Microservice / API Gateway

必背：

- 单体架构流量小时简单，流量大后难扩展。
- SOA / microservice 把系统拆成独立服务。
- 服务之间通过 RPC/API 通信。
- API gateway 统一接收外部请求、路由、过滤、负载均衡。

考场句：

```text
When traffic grows, a monolithic application can be split into independent services. In SOA or microservice architecture, services communicate through RPC or APIs. An API gateway can receive external requests, route them to internal services, apply filters and support load balancing.
```

### 8.17 Marketing funnel 和常见指标

必背：

- Awareness：impressions、reach。
- Consideration：clicks、CTR。
- Conversion：orders、conversion rate、cost per conversion、ROI。
- Engagement：bounce rate。
- E-commerce：GMV、net sales、abandoned cart。

考场句：

```text
The marketing funnel describes how users move from awareness to consideration and conversion. Awareness can be measured by impressions and reach. Consideration can be measured by clicks and CTR. Conversion can be measured by orders, conversion rate, cost per conversion and ROI. E-commerce may also track GMV, net sales and abandoned carts.
```

### 8.18 robots.txt

必背：

- robots.txt 是给 crawler 的声明。
- 可以请求搜索引擎不要索引某些路径。
- 它不是强制安全机制，恶意爬虫可以忽略。

考场句：

```text
robots.txt is a declaration file for web crawlers. It tells search engines which parts of a site should not be crawled or indexed. However, it is not a real security technology, because malicious crawlers may ignore it.
```

### 8.19 UI / UX / IxD / IA

必背：

- UI：用户界面，用户看到和操作的界面。
- UX：用户体验，用户使用产品的整体感受。
- IxD：交互设计，关注用户行为和系统反馈。
- IA：信息架构，关注信息如何组织、导航和呈现。

考场句：

```text
UI is the visible interface that users interact with. UX is the overall experience and feeling when users use a product. Interaction design focuses on user actions and system responses. Information architecture focuses on how information is organized, navigated and presented.
```
