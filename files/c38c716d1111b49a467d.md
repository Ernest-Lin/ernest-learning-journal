# Lec 07 - Introduction to Cryptography

## 1. 总体主线

这一讲讨论的是电子商务安全中最核心的一层：密码学。

核心问题：

> 网络通信会经过很多中间节点。如果消息是明文，任何中间节点都可能看到内容。因此电子商务必须用密码学保护数据、身份和完整性。

这一讲的逻辑可以分成六层：

1. HTTP 为什么不安全，HTTPS 为什么重要。
2. 对称加密如何用同一个 key 加密和解密。
3. 对称加密的主要问题：key 怎么安全交换。
4. 非对称加密如何用 public key 和 private key 解决密钥交换、加密和签名问题。
5. Hash 如何用于完整性校验和数字签名。
6. 现代算法趋势：ECC、国密算法、量子计算和后量子密码。

## 2. HTTP 的问题

HTTP 本身不是加密协议。

也就是说：

- 消息内容是 plain text。
- TCP/IP packet 会经过很多中间节点。
- 中间节点理论上可以看到 packet 里的内容。
- 最大漏洞不是某个网站写错代码，而是 HTTP 协议本身没有加密保护。

在电子商务中，这会带来严重风险：

- 用户账号和密码可能被看到。
- 订单信息可能被看到。
- 支付相关信息可能被看到。
- 中间人可能篡改网页或交易内容。

## 3. HTTPS 的作用

HTTPS 可以理解为：

> 给 HTTP 加了一把锁。

HTTPS 不是把 HTTP 完全换掉，而是在 HTTP 之下加入安全层，用密码学实现：

- Confidentiality：保密性，别人看不到明文内容。
- Integrity：完整性，别人不能悄悄改内容。
- Authentication：身份认证，用户需要确认自己连接的是正确的网站。

重要理解：

> HTTPS 背后不是只用一种算法，而是组合使用对称加密、非对称加密、Hash、数字签名和证书体系。

## 4. Cryptography 包含什么

这一讲把密码学分成四个主要主题：

1. Encryption / Decryption：加密和解密。
2. Key exchange：密钥交换。
3. Hash functions：哈希函数。
4. Digital signature：数字签名。

经典角色：

- Alice：发送方或通信一方。
- Bob：接收方或通信另一方。
- Eve：窃听者或攻击者。

## 5. Encryption 的基本概念

Encryption 是把 readable text 变成 unreadable text 的过程。

常见术语：

- Plaintext：明文，原始可读信息。
- Ciphertext：密文，加密后的信息。
- Key：密钥，加密或解密所需的秘密。
- Encryption algorithm：加密算法。
- Decryption algorithm：解密算法。

重要观点：

> 现代密码学通常假设 algorithm 可以公开，真正需要保密的是 key。

如果没有 key，即使知道算法，也应该很难从 ciphertext 推回 plaintext。

## 6. 古典密码

古典密码的意义不是因为它们今天还安全，而是用来理解密码学思想。

### Scytale Cipher

Scytale 是古希腊斯巴达人使用过的一种加密方式。

做法：

- 把带子绕在特定粗细的棍子上。
- 沿着棍子写消息。
- 拆下带子后文字顺序变乱。
- 只有使用同样粗细的棍子，才能读出原文。

这里的 key 可以理解为棍子的直径或绕法。

### Dialect as Cipher

方言也可以起到类似密码的效果。

如果通信双方使用外人听不懂的语言、方言或术语，Eve 即使听到了声音，也不一定能理解内容。

这说明：

> 加密的核心不是“藏起来不让别人看到”，而是“即使别人看到，也看不懂”。

## 7. Caesar Cipher

Caesar cipher 是移位密码。

加密公式：

```text
E(x) = (x + k) mod 26
```

解密公式：

```text
D(x) = (x - k) mod 26
```

其中：

- `x` 是字母在字母表中的位置。
- `k` 是移动距离，也就是 key。
- `mod 26` 表示超过 26 个字母后从头开始。

例子：

如果 `k = 3`：

- A -> D
- B -> E
- C -> F

缺点：

- key space 太小。
- 只有 26 种可能。
- 可以直接 brute force。
- 也可以通过字母频率分析破解。

## 8. Vigenère Cipher

Vigenère cipher 使用一个 key word 对文本进行多轮移位。

相比 Caesar cipher：

- Caesar：所有字符使用同一个 `k`。
- Vigenère：不同位置使用不同的 `k`。

例子：

```text
Plaintext:  ATTACK
Key:        LEMONL
Ciphertext: LXFOPV
```

优点：

- 比 Caesar 更难破解。
- 同一个字母在不同位置可能被加密成不同字母。

缺点：

- 如果 key 重复使用，会出现规律。
- 重复规律可以被分析。
- 管理很多 key 很困难。

## 9. Enigma 和 Turing

Enigma machine 通过一组轮子自动产生大量变化的 key。

它的思想是：

> 让加密过程随着每个字符不断变化，从而避免简单重复规律。

但历史上 Enigma 最终仍被破解。Alan Turing 在破解 Enigma 和早期计算机发展中扮演了重要角色。

这一部分想表达的重点：

> 安全不是永恒的。某个时代看起来很强的密码，可能会因为数学、工程或计算能力进步而被破解。

## 10. 对称加密

Symmetric encryption 指加密和解密使用同一个 key，或者双方持有等价的共享秘密。

基本流程：

```text
Plaintext + Key -> Ciphertext
Ciphertext + Same Key -> Plaintext
```

优点：

- 速度快。
- 适合加密大量数据。
- 现代 CPU 对某些算法有硬件优化，例如 AES。

缺点：

- Alice 和 Bob 必须事先共享同一个 key。
- 如果没有安全信道，key 交换本身就可能被 Eve 看到。
- key 管理复杂，尤其是参与者很多时。

## 11. DES

DES 是 Data Encryption Standard。

背景：

- 1970 年代 IBM 设计了 Lucifer。
- 美国 NIST 的前身推动 block cipher 标准。
- DES 成为早期重要的对称加密标准。

DES 的问题：

> key length 太短，在现代计算能力下可以被 brute force。

因此 DES 今天已经不再安全。

## 12. Block Cipher

Block cipher 是分组密码。

原因：

> 实际数据通常比 key 长很多，所以不能一次简单处理完整消息，而是要把数据切成 blocks。

基本思想：

- 把长数据分成固定长度的数据块。
- 每个 block 按算法加密。
- 再把多个 encrypted blocks 组合起来。

## 13. Block Cipher Modes

分组密码需要 mode 来规定多个 block 如何处理。

常见 modes：

- ECB
- CBC
- PCBC
- CFB
- OFB
- CTR

### ECB

ECB 是最简单的模式。

问题：

- 相同 plaintext block 会得到相同 ciphertext block。
- 数据模式可能泄露。
- 所以 ECB 在很多真实场景中不够安全。

### 其他 modes

CBC、CFB、OFB、CTR 等模式通过引入前后依赖、初始化向量或计数器来减少模式泄露。

重要观点：

> 不同 mode 不是简单的绝对好坏，而是要看应用场景、性能需求和安全目标。

## 14. 3DES

因为 DES key 太短，后来出现了 3DES。

3DES 的思想：

> 把 DES 做三次，以提高破解成本。

但 3DES 不是理想的长期方案：

- 速度慢。
- 设计较老。
- 后来逐渐被 AES 替代。

## 15. AES

AES 是 Advanced Encryption Standard。

背景：

- Rijndael 由 Vincent Rijmen 和 Joan Daemen 设计。
- 它在 NIST 竞赛中胜出，用于替代 DES。

AES 是现代最重要的对称加密算法之一。

特点：

- 安全性高。
- 性能好。
- 应用广泛。
- 现代 CPU 常有 AES 硬件加速。

## 16. 中国对称加密算法

这一讲提到几种中国商用密码算法：

- SM1：不公开。
- SM4：类似 AES 的分组密码，常用于国内商用密码场景。
- SM7：对称加密算法。
- ZUC：序列密码算法，常见于移动通信场景。

考试重点通常不是算法细节，而是知道：

> 不同国家和行业可能会有自己的密码算法标准。

## 17. 对称加密的核心难题

对称加密真正的难点不是加密速度，而是：

> How to exchange the key safely?

如果 Alice 和 Bob 没有安全信道：

- Alice 把 key 发给 Bob，Eve 可能看到。
- Eve 看到 key 后，就能解密之后的所有消息。
- 所以需要一种办法，在公开网络上生成或交换共享密钥。

这引出非对称密码和 Diffie-Hellman key exchange。

## 18. 非对称加密

Asymmetric algorithms 使用一对 key：

- Public key：公钥，可以公开。
- Private key：私钥，必须保密。

基本思想：

> 公钥可以让所有人知道，但只有私钥持有者能完成某些关键操作。

非对称加密解决了对称加密中 key exchange 的大问题。

但它也有缺点：

- 计算成本高。
- 通常不适合直接加密大量数据。
- 实际系统中常用它来交换或保护对称密钥。

## 19. 模运算基础

这一讲用 `^` 和 `%` 解释非对称密码的数学基础。

重要结论：

```text
a^b % p = [(a % p)^b] % p
```

原因：

如果：

```text
a = mp + q
```

那么：

```text
a % p = q
```

将 `a^b` 展开后，大部分项都含有 `p`，对 `p` 取模后会变成 0，最后剩下 `q^b % p`。

这个性质让我们可以在计算大指数时不断取模，避免数字无限变大。

关键词：

- Modular arithmetic：模运算。
- Exponentiation：指数运算。
- Modular exponentiation：模幂运算。

## 20. Diffie-Hellman Key Exchange

Diffie-Hellman，简称 DH，用来在公开信道上生成共享密钥。

公开参数：

- `p`：一个素数。
- `g`：`p` 的 primitive root。

私有参数：

- Alice 选择私钥 `a`。
- Bob 选择私钥 `b`。

公开交换：

```text
Alice public A = g^a mod p
Bob public B   = g^b mod p
```

生成 session key：

```text
Alice computes: B^a mod p = g^(ab) mod p
Bob computes:   A^b mod p = g^(ab) mod p
```

所以 Alice 和 Bob 最终得到同一个 shared key。

Eve 可以看到：

- `p`
- `g`
- `A`
- `B`

但 Eve 不知道：

- `a`
- `b`
- `g^(ab) mod p`

安全基础：

> 从 `g^a mod p` 反推出 `a` 很难，这就是离散对数问题。

## 21. DH 的局限

DH 可以让双方生成共享密钥，但它本身不能确认身份。

问题：

> Alice 怎么知道收到的 public value 真的是 Bob 发来的？

如果 Eve 位于中间，可以分别和 Alice、Bob 建立密钥，形成 man-in-the-middle attack。

因此实际系统中，DH 需要配合：

- 数字签名。
- 证书。
- 公钥基础设施，PKI。

## 22. RSA

RSA 是经典非对称算法，由 Rivest、Shamir 和 Adleman 在 1977 年提出。

RSA 使用 key pair：

- Public key：通常写作 `(e, N)`。
- Private key：通常写作 `(d, N)`。

核心要求：

```text
g^(de) mod N = g
```

这样就可以实现：

```text
Encryption: ge mod N = C
Decryption: Cd mod N = g
```

也可以反向用于签名：

```text
Sign:   gd mod N = S
Verify: Se mod N = g
```

## 23. Euler Totient Function

Euler's totient function，记作 `φ(x)`。

含义：

> `φ(x)` 是从 1 到 x 中，与 x 互质的数字个数。

重要性质：

- 如果 `x` 是素数，那么 `φ(x) = x - 1`。
- 如果 `m` 和 `n` 是素数，那么 `φ(mn) = (m - 1)(n - 1)`。

RSA 里：

```text
N = m * n
φ(N) = (m - 1) * (n - 1)
de = kφ(N) + 1
```

这样就可以找到满足条件的 `d` 和 `e`。

## 24. RSA 示例

课件例子：

```text
m = 29
n = 83
N = 29 * 83 = 2407
φ(N) = (29 - 1) * (83 - 1) = 2296
e = 5
k = 4
d = (4 * 2296 + 1) / 5 = 1837
```

所以 key pair 是：

```text
Public key:  {5, 2407}
Private key: {1837, 2407}
```

测试：

```text
Original: 199
Encryption: 199^5 mod 2407 = 1557
Decryption: 1557^1837 mod 2407 = 199
```

## 25. RSA 为什么难破解

RSA 的安全性依赖一个事实：

> 已知 `N = m * n` 很容易，但只知道很大的 `N`，想分解出 `m` 和 `n` 很难。

如果攻击者能把 `N` 分解成两个素数：

- 就能计算 `φ(N)`。
- 就可能推出 private key `d`。
- RSA 就被破解。

因此 RSA 需要足够长的 key。

课件强调：

- 1024-bit RSA 在今天已经不够安全。
- 至少需要 2048-bit。
- 量子计算如果成熟，会严重威胁 RSA。

## 26. RSA 的两种应用

### 1. 加密

别人用 Alice 的 public key 加密：

```text
Ciphertext = g^e mod N
```

只有 Alice 有 private key，可以解密：

```text
Plaintext = C^d mod N
```

用途：

> 保护信息内容，让只有私钥持有者能读。

### 2. 数字签名

Alice 用 private key 签名：

```text
Signature = g^d mod N
```

别人用 Alice 的 public key 验证：

```text
Verified result = S^e mod N
```

用途：

> 证明消息确实来自 Alice，并且没有被篡改。

## 27. Symmetric vs Asymmetric

### 对称加密

优点：

- 快。
- 适合大量数据。
- 实现成熟。

缺点：

- key 共享困难。
- 多用户系统中 key 管理复杂。

### 非对称加密

优点：

- public key 可以公开。
- 更适合身份认证、密钥交换和数字签名。

缺点：

- 慢。
- 计算成本高。
- 不适合直接加密大量正文。

实际系统通常结合二者：

> 用非对称加密解决身份和密钥问题，再用对称加密传输大量数据。

这也是 HTTPS / TLS 的基本思路。

## 28. Digital Signature

数字签名不是把手写签名图片贴到文档上。

手写签名图片的问题：

- 可以被复制。
- 可以被截图。
- 不能可靠证明内容没有被改。
- 无法和具体文件内容强绑定。

真正的 digital signature 需要密码学保证。

数字签名要解决两个问题：

1. Authentication：确认发送者身份。
2. Integrity：确认消息没有被篡改。

## 29. Hash

Hash 是 message digest。

定义：

> Hash function 把任意长度输入转换成固定长度输出。

特点：

- Input 可以很长。
- Output 长度固定。
- 设计上是 one-way，不能从 hash 反推原文。
- 原文很小的变化应该导致 hash 完全不同。
- 输出空间要足够大，减少碰撞风险。

## 30. 常见 Hash 算法

这一讲提到：

- MD5
- SHA series

### MD5

MD5 曾经被广泛使用，但现在已经不适合安全要求高的场景。

原因：

- 已经发现碰撞攻击。
- 不能再作为强安全签名基础。

### SHA

SHA 系列是更现代、更常用的 hash algorithm family。

实际系统中常见：

- SHA-256
- SHA-384
- SHA-512

## 31. Hash 的用途

Hash 常用于 verifying integrity。

例子：

软件下载页面发布：

```text
file.zip
SHA-256: abc123...
```

用户下载文件后本地计算 hash：

- 如果本地 hash 和官网发布的 hash 一样，说明文件大概率没有被改。
- 如果不同，说明文件可能损坏或被篡改。

## 32. 为什么签名通常签 Hash

直接用 RSA 签整个文件有两个问题：

- 文件可能很大，RSA 计算成本高。
- 签名输出和处理会很低效。

所以真实系统通常是：

```text
Message -> Hash -> Sign the hash
```

验证时：

```text
Message -> Hash
Signature -> Verify -> Compare hash
```

这样可以同时保证：

- 文件内容一旦变化，hash 会变化。
- 只有私钥持有者能生成有效签名。
- 公钥可以验证签名是否匹配。

## 33. ECC

ECC 是 Elliptic Curve Cryptography，椭圆曲线密码。

特点：

- 数学基础比 RSA 更复杂。
- 使用特定曲线参数。
- 在相同安全级别下，key 可以比 RSA 短。
- 因为 key 更短，通常性能更好。

重要观点：

> 现代应用越来越偏向 ECC，因为它能用较短 key 达到相近安全强度。

区块链如 Bitcoin 也使用 ECC 相关算法。

## 34. 中国非对称加密算法

这一讲提到：

- SM2：基于 ECC 的中国商用密码算法，使用一组特定参数。

可以和前面的 SM4 对应记忆：

- SM2：非对称 / ECC。
- SM4：对称 / block cipher。

## 35. 不同算法的成本

课件强调：

- RSA 需要较长 key，因此计算成本高。
- AES 在现代 CPU 上通常有硬件优化。
- 对称加密在相同 key length 下通常比非对称加密更难 brute force。
- 不能只看 key length 直接比较不同算法的安全性。

更合理的比较方式：

> 比较达到相近 brute force cracking 成本时，各算法需要多少资源。

## 36. 安全性的现实理解

重要总结：

> All keys can be broken. The main issue is computing resource and whether it is worth breaking.

也就是说，安全不是绝对不能破解，而是让破解成本高到不现实。

影响安全性的因素：

- key length。
- 算法设计。
- 实现是否正确。
- 计算能力变化。
- 新数学突破。
- 量子计算等新技术。

## 37. 量子计算的影响

Shor algorithm 可以威胁 RSA 这类依赖大整数分解难题的算法。

课件表达的重点：

- 如果量子计算足够强，RSA 会变得不安全。
- 目前公开报道中能处理的数字还非常有限。
- 但未来风险需要提前考虑。

## 38. Post-Quantum Cryptography

Post-quantum cryptography 指希望在量子计算时代仍然安全的密码算法。

课件提到：

- Lattice encryption：格密码。

后量子密码的目标：

> 即使攻击者拥有量子计算机，也很难破解。

## 39. Quantum Key

课件最后提到 quantum key 可能用于对抗 quantum computing。

可以理解为：

- Quantum computing 会威胁某些传统密码算法。
- Quantum key distribution 等量子通信技术可能提供新的密钥分发方式。

考试层面记住：

> 量子技术既可能是攻击力量，也可能成为新的安全工具。

## 40. 一句话串起整讲

这讲可以用一条线记：

> HTTP 明文不安全，所以需要加密；对称加密快但 key 难交换；非对称加密解决 key exchange 和 signature，但速度慢；Hash 提供完整性摘要；现代系统把这些技术组合起来，形成 HTTPS、数字签名和安全电子商务。

## 41. 高频考点

### HTTP vs HTTPS

- HTTP 明文传输。
- HTTPS 使用密码学保护通信。
- HTTPS 提供保密性、完整性和身份认证。

### 对称加密

- 同一个 key 加密和解密。
- 快，适合大量数据。
- 难点是 key exchange。
- DES 已不安全。
- AES 是现代主流。

### Block cipher

- 数据被切成 blocks。
- ECB 简单但会泄露模式。
- CBC、CFB、OFB、CTR 等适合不同应用。

### Diffie-Hellman

- 用公开参数在不安全信道上生成 shared key。
- 安全基础是离散对数问题。
- 单独使用不能认证身份，可能被中间人攻击。

### RSA

- 公钥 `(e, N)`，私钥 `(d, N)`。
- 安全基础是大整数分解困难。
- 可用于加密，也可用于数字签名。
- 1024-bit 不够安全，至少 2048-bit。

### Hash

- 任意长度输入，固定长度输出。
- 单向。
- 小变化导致大不同。
- 用于完整性校验和数字签名。

### Digital signature

- 不是签名图片。
- 通常签 message hash。
- 用 private key 签名，用 public key 验证。
- 证明来源和完整性。

### ECC

- 椭圆曲线密码。
- 同等安全级别下 key 更短。
- 现代应用常用。
- SM2 是基于 ECC 的中国非对称算法。

## 42. 易混点

### Encryption 不等于 Hash

- Encryption 可以 decrypt 回原文。
- Hash 设计上不能 decode 回原文。

### Public key 不是 secret

- Public key 可以公开。
- Private key 必须保密。

### RSA 加密和签名方向不同

- 加密：public key 加密，private key 解密。
- 签名：private key 签名，public key 验证。

### DH 不等于身份认证

- DH 可以生成 shared key。
- 但 DH 本身不能证明对方是谁。
- 所以需要证书或签名配合。

### Key length 不能跨算法直接比较

- AES-256 和 RSA-2048 的数字不能简单说 256 比 2048 小所以更弱。
- 不同算法依赖不同数学难题。
- 要比较相近攻击成本下的安全级别。

## 45. 期末最可能考的密码学题型

### 1. Diffie-Hellman 计算 public key

题目通常给：

```text
p = prime number
g = generator / primitive root
private key = b
```

要求算：

```text
Public key = g^b mod p
```

例子：

```text
p = 151
g = 6
Bob private key = 13
Bob DH public key = 6^13 mod 151 = 54
```

答题时不要只写结果，最好写公式和代入过程：

```text
B = g^b mod p = 6^13 mod 151 = 54
```

### 2. RSA digital signature

题目可能要求：

> 对 DH public key 做 digital signature，不需要 hashing。

如果签名者是 Bob，就用 Bob 的 private key。

例如 Bob 的 RSA key 是：

```text
Public key:  (7, 119)
Private key: (55, 119)
Message: Bob's DH public key = 54
```

签名：

```text
S = M^d mod N
S = 54^55 mod 119 = 96
```

所以 Bob 发给 Alice 的内容应该包括：

```text
DH public key = 54
Digital signature = 96
```

### 3. RSA signature verification

Alice 收到 Bob 的 DH public key 和 signature 后，需要用 Bob 的 public key 验证。

公式：

```text
M' = S^e mod N
```

代入：

```text
M' = 96^7 mod 119 = 54
```

然后比较：

```text
M' == received DH public key
```

如果相等，说明这个 DH public key 确实由 Bob 的 private key 签过，并且传输中没有被改。

标准答题句：

> Alice uses Bob's public key to decrypt / verify the signature. If the recovered value equals the received DH public key, Alice can verify the originality and integrity of the key.

注意：

- 加密是 public key 加密，private key 解密。
- 签名是 private key 签名，public key 验证。
- 这两个方向很容易考，也很容易混。

### 4. Vigenere cipher 解密

题目可能给：

```text
Ciphertext
Key
Vigenere table
```

要求填 plaintext / key / ciphertext 表格。

解密规则：

```text
Plaintext = Ciphertext - Key mod 26
```

如果 key 比 ciphertext 短，就循环重复 key。

例如：

```text
Ciphertext: K A T V V G F U Q Z
Key:        I M I S D M T I M I
Plaintext:  C O L D S U M M E R
```

用表格做题时：

- 先把 key 循环写满。
- 对每一列做一个字母的 Vigenere 解密。
- 最后拼出 plaintext。

### 5. 对称加密 vs 非对称加密哪个快

简答题常见问法：

> Which is typically faster: symmetric encryption or asymmetric encryption? Please provide your reasons.

标准答案：

> Symmetric encryption is typically faster. It uses the same shared key and simpler operations, so it is efficient for encrypting large amounts of data. Asymmetric encryption uses a public/private key pair and relies on heavier mathematical operations such as modular exponentiation or elliptic curve operations, so it is slower. Therefore, real systems often use asymmetric encryption for key exchange or digital signatures, and symmetric encryption for bulk data encryption.

中文理解：

- 对称加密更快。
- 非对称加密更慢但能解决 key exchange、authentication、signature。
- HTTPS/TLS 通常两者结合。

## 46. Lec 07 复习优先级

### 必须会算

- `g^private mod p` 算 DH public key。
- `M^d mod N` 算 RSA signature。
- `S^e mod N` 验证 RSA signature。
- Vigenere cipher 按 key 解密。

### 必须会解释

- 为什么 HTTP 不安全，HTTPS 为什么需要密码学。
- 对称加密快，但 key exchange 难。
- 非对称加密慢，但 public key 可以公开。
- DH 可以生成 shared key，但不能单独认证身份。
- RSA 可以用于 encryption，也可以用于 digital signature。
- Hash 是 one-way message digest，通常签 hash 而不是签全文。

### 不需要深挖数学证明

下面内容理解即可，通常不需要完整推导：

- Euler theorem 的严格证明。
- RSA 大数分解的完整数学细节。
- ECC 曲线公式。
- 后量子密码的具体算法实现。

## 49. 验签找出被篡改的 DH Key

题型：

```text
Alice sends two possible D-H public keys with digital signatures:
[D-H key: 92, RSA sign: 9]
[D-H key: 15, RSA sign: 42]

Alice's RSA public key = (7, 187)
Find the valid key.
```

思路：

收到的是 Alice 发来的 key，所以要用 Alice 的 public key 验证签名。

验证公式：

```text
M' = S^e mod N
```

如果：

```text
M' == received D-H key
```

则签名有效，key 没有被篡改。

候选 1：

```text
M' = 9^7 mod 187 = 70
70 != 92
```

所以 `[D-H key: 92, RSA sign: 9]` 无效，可能被 Eve 篡改。

候选 2：

```text
M' = 42^7 mod 187 = 15
15 == 15
```

所以有效 key 是：

```text
[D-H key: 15, RSA sign: 42]
```

标准答题句：

> Bob verifies each signature using Alice's public key. The recovered value from the signature must equal the received D-H public key. Since `42^7 mod 187 = 15`, the second key is valid.

## 50. 计算 DH Public Key 和 Session Key

题型：

```text
D-H parameters:
p = 227
g = 8

Bob private key = 61
Alice valid D-H public key = 15
```

### Step 1: Bob 的 D-H public key

公式：

```text
B = g^b mod p
```

代入：

```text
B = 8^61 mod 227 = 154
```

所以 Bob 的 D-H public key 是：

```text
154
```

### Step 2: Session key

Bob 用 Alice 的有效 D-H public key 和自己的 private key 计算 session key。

公式：

```text
Session key = A^b mod p
```

代入：

```text
Session key = 15^61 mod 227 = 206
```

所以 session key 是：

```text
206
```

注意：

- 如果题目已经让你先验证 Alice 的 public key，那么 session key 必须使用验证有效的那个 key。
- 不要拿被篡改的 DH key 去算 session key。

## 51. Vigenere 加密题

第一套卷考的是 Vigenere 解密，第二套卷考的是 Vigenere 加密。

题型：

```text
Plaintext: helloworld
Key: CANSAT
```

先统一大写：

```text
Plaintext: H E L L O W O R L D
Key:       C A N S A T C A N S
```

加密规则：

```text
Ciphertext = Plaintext + Key mod 26
```

逐字母结果：

```text
Plaintext:  H E L L O W O R L D
Key:        C A N S A T C A N S
Ciphertext: J E Y D O P Q R Y V
```

所以答案：

```text
JEYDOPQRYV
```

### Vigenere 加密和解密对比

加密：

```text
C = P + K mod 26
```

解密：

```text
P = C - K mod 26
```

记忆：

- Encrypt：往后移。
- Decrypt：往前移。
- Key 不够长就循环重复。

## 52. 为什么 RSA 能认证，但 DH 不能

这是第二套卷的 5 marks 简答题。

核心答案：

> RSA can be used for authentication because it supports digital signatures. A sender signs data using the private key, and others verify the signature using the corresponding public key. Since only the private key owner can generate a valid signature, RSA can prove the sender's identity. D-H only establishes a shared session key over a public channel. By itself, D-H does not prove that the received public value really comes from Alice or Bob, so it is vulnerable to man-in-the-middle attacks unless combined with signatures or certificates.

中文拆解：

- RSA 有 public/private key pair。
- private key 只有本人有。
- 用 private key 签名，别人用 public key 验证。
- 因此可以证明“这个消息确实来自私钥持有人”。
- DH 的目标只是让双方生成 shared key。
- DH public value 本身没有身份信息。
- Eve 可以替换 DH public value。
- 所以 DH 单独不能 authentication。

考试短答模板：

```text
RSA can provide authentication because it can generate digital signatures with the private key and verify them with the public key. Only the private key holder can produce a valid signature.
D-H only allows two parties to derive a shared session key. It does not verify the identity of the party who sends the D-H public key, so it cannot provide authentication by itself and may suffer from man-in-the-middle attacks.
```
